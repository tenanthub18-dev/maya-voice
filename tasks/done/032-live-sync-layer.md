# 032 Live sync layer (cross-tab + realtime), no duplicated data
Depends on 031 (the `live-rev` cookie nonce and `invalidateAfterWrite`). Architecture (Claude): server components render from the one `DataSource`; the client keeps ONLY a tiny signal store (which scope changed, connection state), never entity data. A signal triggers a coalesced `router.refresh()`. In-tab propagation uses React 19 `useSyncExternalStore` (sub-millisecond, no library). Network hops (other tab, other device) are bounded by transport, not by us. No new dependencies (BroadcastChannel and `@supabase/ssr` already exist).

## Files (all under apps/web/lib/live/ unless noted)
- `events.ts`: `type LiveScope = 'restaurant'|'calls'|'bookings'|'orders'|'messages'|'agent'|'usage'`; `LiveEvent = {scope: LiveScope; source: 'local'|'broadcast'|'realtime'; at: number}`; `scopesForPath(pathname)` mapping each route to the scopes it renders (/home -> calls,bookings,orders,messages,restaurant,usage; /calls -> calls; /bookings; /orders; /agent -> agent,restaurant; /settings and /admin -> restaurant,usage; layout/shell always restaurant). Single table, tested for every route in `app/`.
- `store.ts`: framework-free external store: `getSnapshot/subscribe`, state `{connection: 'idle'|'live'|'reconnecting'|'offline'|'demo', lastEventAt}`; `emit(event)` fan-out to listeners; selectors via `useSyncExternalStore` so only components reading `connection` re-render. Module-level singleton guarded for SSR (no state on the server; server snapshot is constant).
- `coalesce.ts`: `createRefreshScheduler({refresh, delayMs=120, maxWaitMs=1000})`: bursts of events collapse into one refresh (leading call for `source==='local'|'broadcast'` runs immediately, trailing for realtime). Pure, takes an injectable clock/timers; fully unit tested with fake timers (50 events in 100 ms -> <= 2 refreshes; error in refresh does not kill the scheduler).
- `transports/broadcast.ts`: `createBroadcastTransport(channelName='maya-live')` over `BroadcastChannel`; posts `{scope, nonce}`; degrade to no-op when `BroadcastChannel` is undefined. Works in mock and live mode (same-browser tabs).
- `transports/supabase-realtime.ts`: `createRealtimeTransport({client, restaurantId})` subscribing with `client.channel(...).on('postgres_changes', {event:'*', schema:'public', table, filter:`restaurant_id=eq.${restaurantId}`}, cb).subscribe(statusCb)` for tables calls, bookings, orders, messages, agent_versions, restaurants (map table -> scope). Report `SUBSCRIBED -> live`, `CHANNEL_ERROR|TIMED_OUT -> reconnecting`, `CLOSED -> offline`; unsubscribe on cleanup. Cite https://supabase.com/docs/guides/realtime/postgres-changes in a comment. RLS already applies to Realtime; do not add any service-role usage in the browser. The client factory is `lib/data/supabase/client.ts`. Tests inject a FAKE channel object (no network) and assert the filter string, status mapping and cleanup. Only loaded via dynamic `import()` when `DATA_SOURCE==='supabase'` (never bundled for the demo).
- `components/live-sync.tsx` (client): props `{revisionNonce: string|null, restaurantId: string, mode: 'demo'|'supabase'}`. On mount: create broadcast transport (+ realtime transport when mode is supabase), subscribe the scheduler. LOOP SAFETY (required): keep `lastSeenNonce` in a ref. When the `revisionNonce` prop changes and differs from `lastSeenNonce`, this tab originated a write -> post one broadcast carrying the nonce and set `lastSeenNonce`. When a broadcast arrives, set `lastSeenNonce = msg.nonce` BEFORE refreshing so the refreshed layout's nonce prop equals it and does NOT rebroadcast. Test this exact ping-pong case with two simulated tabs (no infinite loop; exactly one refresh in the receiving tab). Only refresh when the event scope intersects `scopesForPath(usePathname())`; pause (queue one refresh) while `document.visibilityState==='hidden'` and refresh on `visibilitychange` to visible; typing guard: never refresh while `document.activeElement` is an input/textarea/select inside `<main>` AND the event source is not 'local'; retry when it blurs (so a remote update never wipes what the user is typing).
- Mount `<LiveSync/>` once in the authenticated shell (`components/app-shell.tsx` / its server parent passes `revisionNonce` read from `cookies().get('live-rev')?.value`, `restaurantId` from `getCurrentRestaurant()`, `mode` from `isDemoData()`). Add a small status chip in the shell header: `Live` (green dot), `Reconnecting...`, `Offline`, `Demo data` reusing the existing demo banner text; role="status", `aria-live="polite"`, EN+FR strings in messages (no brand literals), ≥44px tap target not needed (non-interactive). Respect `prefers-reduced-motion` for any pulse.
