# 029 Web security hardening (apps/web)
Read PRD section 9 security list. Implement and test:
1. Security headers in next.config (and proxy): strict CSP (nonce-based for scripts; allow only self + Stripe/Supabase/Telnyx origins actually used; frame-ancestors none), HSTS, X-Content-Type-Options, Referrer-Policy strict-origin-when-cross-origin, Permissions-Policy (microphone=self only on the test-call route), COOP/CORP. CSP must not break the app: add a test that renders key pages and inspects headers.
2. SSRF guard for website import (`/api/import`): only http/https, reject userinfo, non-standard ports, private/loopback/link-local/metadata IPs (v4 and v6, incl. DNS-rebinding by resolving and re-checking, and redirects re-validated), length limits; table tests with hostile URLs.
3. Rate limits per PRD: 10 import jobs/hour/org, 5 number purchases/day/org, login attempts, webhook endpoints; abstraction already exists - add persistent limiter interface (Supabase table or in-memory for mock) and tests.
4. Mutating routes/server actions: origin/CSRF check (Origin header must match app origin), JSON content-type enforcement, body size limits, zod strict schemas (reject unknown keys), uniform errors without stack traces or internals; a test enumerating every route handler under app/api asserts it has auth OR signature verification (fail the test for any new unprotected route).
5. XSS: transcripts, FAQs, menu text, caller names are untrusted: assert no dangerouslySetInnerHTML anywhere (lint rule + test), escape in emails, safe handling of RTL/bidi control characters in transcript text.
6. Recordings/audio served only via short-lived signed URLs (5 min) generated server-side after authorization; test expiry and cross-tenant denial.
7. Internal worker endpoints (/internal/publish, /webrtc/offer): HMAC with 5-minute window, shared helper with test vectors, replay window test (verify both web signer and worker verifier agree - add a cross-language fixture file used by both test suites).
8. Secrets hygiene: scripts/check-secrets.sh runs gitleaks on the tree; ensure no secret-like values in repo; service-role key never importable from client bundles (eslint no-restricted-imports + a build-output grep test for `service_role`/`sb_secret_`).
9. Auth: session cookie flags, logout invalidation, invite token single-use + expiry, magic link/OAuth callback error handling, open-redirect tests (extend existing).
