# 028 Worker resilience: PRD section 8 provider failures and caller behaviour (apps/worker only)
Read PRD sections 3 (silence rule, language switching) and 8. The rule: the caller never hears silence or a crash; degrade or transfer. Implement as small, separately tested modules under apps/worker/src/voice_receptionist_worker/resilience/ and wire into the pipeline (cite Pipecat source paths for any hook used; do not invent APIs):
1. Failure policy state machine (`policy.py`): per-call counters; STT drop -> reconnect within 1 s and replay buffered audio, after 2 failures cached 'trouble hearing you' + transfer; TTS fail -> retry once then fallback TTS config (`tts_fallback` in config/providers.yaml, may stay VERIFY-gated and skipped with a log if unset) for rest of call; LLM first-token > 2.5 s -> cached filler, retry once with fallback model (`llm_fallback`), second failure -> cached apology + transfer or take_message; tool timeout 3 s -> say it could not complete, never claim success, idempotency prevents duplicates; Supabase unreachable -> FAQ-only from cached config + local message queue flushed later (`offline_queue.py`, file-backed, bounded, tested); spend cap/unpaid -> immediate forward to transfer number.
2. Call limits: wrap-up at 9 min, polite end at 10 min; silence rule; DTMF '0' always transfers, other keys ignored; blocked/private caller ID -> ask for a number; unsupported language -> apologise once in English, offer English/French/transfer; honest AI disclosure when asked.
3. Noise: after 3 false barge-ins in 30 s raise VAD threshold (config-driven numbers).
4. Prompt-injection and abuse: tool layer validates EVERY argument server-side (types, ranges, restaurant scoping from the call context, never from model text); model cannot choose restaurant_id/phone/amount fields that the server knows; refuse transfer_call outside hours; send_payment_link only when flag on; abusive caller -> one warning then goodbye + qa_flag; off-topic -> one-line redirect (prompt rules, with unit tests on the validator not on the LLM).
5. /telnyx/texml: set TeXML failover so a crashed/unreachable worker forwards to the transfer number (check docs/api/telnyx README for the failover mechanism; if only configurable in the Telnyx portal, document it in docs/GO-LIVE.md instead and add a worker-side startup log line).
6. Cached audio phrases list (apology, filler, transfer, trouble-hearing, goodbye) per language as data in config, with a test that every phrase exists for all 5 launch languages.
Tests for every row above using fakes (no network): simulated STT/TTS/LLM/tool failures asserting the exact fallback sequence and that no path ends with silence.
