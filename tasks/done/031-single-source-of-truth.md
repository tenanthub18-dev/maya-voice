# 031 Single source of truth (brand, restaurant identity, write invalidation)
Owner request: "one source of truth, everything picks up from it, update once and everything follows". Architecture decision (Claude): the SERVER stays the only owner of business data (`DataSource`). Do NOT mirror server data into a client store (that creates a second source of truth). Fix duplication at three seams only. Surgical: no new dependencies.

## Seam 1: product brand + persona default (`apps/web/lib/brand.ts`, new)
- Export one frozen object, e.g. `BRAND = {product: {en: 'Maya Reception', 'fr-CA'/fr: 'Réception Maya'}, defaultPersonaName: 'Maya'}` and `getProductName(locale)`. Product name is NOT the restaurant name and NOT the persona name (three distinct concepts).
- Remove every hand-typed copy: `messages/en.json` + `messages/fr.json` keys `app.name`, `landing.brand`, `auth.brand` (and any other brand literal; "Hostline" must disappear), `app/layout.tsx` metadata title (use `generateMetadata` with the active locale), `components/app-shell.tsx` (`app('name')` x4 incl. the avatar initial), `components/landing-page.tsx`, `components/auth-panel.tsx`, `lib/auth/invitation-server.ts` (from-name + subject), `docs/design-system.md`, `lib/data/mock/seed.ts` persona default.
- Server components read it via `getProductName(locale)`; client components receive it as a prop from the nearest server parent (do not import server-only helpers into client files).
- Test `tests/single-source.test.ts`: recursively scan `apps/web/{app,components,lib,messages}` (exclude `lib/brand.ts`, `tests/`, `e2e/`) and fail if the literals `Hostline`, `Maya Reception`, `Réception Maya` appear. Also assert `getProductName('en') !== BRAND.defaultPersonaName` is a separate value and that changing `BRAND` is the only edit needed (import it in the test and check landing + shell render the changed value via vi.mock of `lib/brand`).

## Seam 2: restaurant identity read once, everywhere
- Add `apps/web/lib/restaurant.ts`: `export const getCurrentRestaurant = cache(() => getDataSource().getRestaurant())` using React `cache` (per-request dedupe). Every page/layout/component that needs the restaurant name calls this; no other path to the name (`dashboard-screen.tsx`, `admin` list, shell header, digest, notifications).
- Replace the hard-coded `'Harbour Table'` in `app/api/cron/digest/route.ts` mock repository with the name from `getCurrentRestaurant()` (mock mode only) so the digest follows renames.
- Show the restaurant name in the desktop sidebar header area under the product name and in the mobile header (small, truncated, `title` attr for the full name). It must come from the layout's single call, passed down as a prop.
- Test: with the mock data source, call `updateRestaurantBasics({name:'Renamed Cafe', address})`, then assert `getCurrentRestaurant()` (fresh request scope), the dashboard title text, the admin list row, and the digest recipient all show `Renamed Cafe`. No component may hard-code a name.

## Seam 3: one invalidation helper for writes (`apps/web/lib/data/invalidate.ts`, new)
- Today each action hand-lists paths (`revalidatePath('/settings')` etc, 22 call sites in app/{agent,settings,bookings,orders,home,onboarding,calls}/**/actions.ts). Replace with one `invalidateAfterWrite()` that (a) calls `revalidatePath('/', 'layout')` (Next 16 docs: https://nextjs.org/docs/app/api-reference/functions/revalidatePath) so every route re-reads shared data, and (b) sets an httpOnly, SameSite=Lax, Secure-in-production cookie `live-rev` to a fresh random nonce (`crypto.randomUUID()`), path `/`, maxAge 1 day, via `cookies()` from `next/headers` (this nonce is consumed by brief 032; document that in a code comment).
- Replace all direct `revalidatePath` calls in actions with it. Test `tests/invalidate.test.ts`: (1) scan fails if any `actions.ts` outside `lib/data/invalidate.ts` imports `revalidatePath`; (2) unit test with mocked `next/cache` and `next/headers` proving both effects and that the nonce changes each call.
- `docs/ARCHITECTURE.md` (new, <60 lines): the three seams, "server owns data, client holds no copies", and how to add a new entity (add to DataSource, call `invalidateAfterWrite()` in its action).
