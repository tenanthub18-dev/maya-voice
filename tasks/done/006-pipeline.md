# M1.2 Pipecat pipeline + latency logging (PRD §3, M1)
Read the installed pipecat-ai source and official docs (https://docs.pipecat.ai) before coding; cite URLs. Add pipecat-ai with extras needed for Soniox, Silero VAD, Google (Gemini) and the Telnyx serializer, pinned via uv. In apps/worker/src/voice_receptionist_worker/pipeline/: build_pipeline(config, websocket, stream info) wiring TelnyxFrameSerializer -> Silero VAD -> SonioxSTTService -> Gemini LLM service -> SonioxTTSService, streaming, with barge-in enabled. Provider/model/voice IDs come from config/providers.yaml (fill the VERIFY keys only with values confirmed in official docs/model-list endpoints; otherwise leave VERIFY and make startup fail with a clear 'VERIFY provider config' error). Hard-coded dev restaurant in config/dev-restaurant.yaml (name, hours, 5 menu items) used to build the system prompt (spoken style rules from PRD §3: 1-2 sentences, under 25 words, short acknowledgement opener). Per-turn latency logger recording eot, stt, llm_ttft, tts_ttfb, total ms to a JSONL file (path from env) using Pipecat's metrics/observers. Unit tests (no network, no real keys) for: prompt builder, config loader failing on VERIFY, latency record aggregation (p50/p95). Wire /ws to run the pipeline only when config is valid.
